# SEO Audit — carlmadelo.com

Single-page portfolio, Duda web design services. Audited against the delivered `index.html`.

## Part 1 — Audit findings

### P0 — Fixed in the new `index.html`

| # | Issue | Why it mattered | Fix applied |
|---|---|---|---|
| 1 | **Zero keywords in `<h1>`** — "Design that performs." | The strongest on-page signal on the site carried no topical meaning | `Duda websites that perform.` — keyword + brand voice retained |
| 2 | **All seven `<h2>`s were keyword-free** ("Curated for clarity", "What I offer", "Built with") | Google had almost no topical signal below the title tag | Rewritten to carry intent while keeping the two-line serif rhythm |
| 3 | **`twitter:card = summary_large_image` with no image declared** | Every share on X/LinkedIn/Slack rendered as a bare link | Added `og:image`, `og:image:width/height/alt`, `twitter:image` → **you must create `/og-image.jpg` at 1200×630** |
| 4 | **Hero portrait was a CSS background** | Zero alt text, zero image indexation, no `fetchpriority` on the LCP element | Converted to a real `<img>` with alt, explicit dimensions and `fetchpriority="high"` |
| 5 | **Schema used `ProfessionalService` with no `address`** | `ProfessionalService` is a `LocalBusiness` subtype; declaring `priceRange` and `areaServed: Worldwide` with no address is a content mismatch | Rebuilt as `@graph`: `Person` + `ProfessionalService` + `WebSite` + `WebPage` + `ItemList` (portfolio) + `FAQPage` |
| 6 | **FAQ section existed with no `FAQPage` markup** | Six well-written Q&As invisible to structured-data parsers and to AI answer engines | `FAQPage` added, mirroring visible copy exactly |
| 7 | **Three dead `href="#"` links** (LinkedIn, ×3) | Dead internal links + no `sameAs` signal for entity recognition | Pointed at a real LinkedIn URL and added to `sameAs` — **verify the URL is correct** |
| 8 | **Title led with the brand name** | "Carl Madelo" has no search volume; the keyword was pushed past position 3 | `Duda Web Designer & Developer \| Carl Madelo` (47 chars) |
| 9 | **Meta description 172 chars** | Truncated in SERPs | Trimmed to 146 chars |
| 10 | **No favicon, apple-touch-icon or manifest** | Missing brand signals; browser default icon | Link tags added — **assets still need creating** |
| 11 | **`robots` was bare `index, follow`** | No large image previews in SERPs | `max-image-preview:large, max-snippet:-1` added |
| 12 | **Skip link targeted `#work`, not the main region** | Skipped over the hero | Retargeted to `#main`, and `<main>` now has the id |
| 13 | **Google Fonts loaded 2 unused weights** (Fraunces 300, 600) | Wasted bytes on the render-blocking request | Trimmed to weights actually used |
| 14 | **No LCP preload** on `hero-bg.png` / `portrait.png` | Both discovered late in CSS | `<link rel="preload" as="image">` added for both |
| 15 | **Footer `<h4>`s with no `<h3>` above them** | Broken heading hierarchy | Converted to `<h2>` inside `<nav>` landmarks with `aria-label` |
| 16 | **Thin body copy (~700 words total)** | Not competitive for any commercial Duda term | Work cards now carry sector + description; services and about copy expanded; new Guides section |
| 17 | **`stack-card` buttons had `aria-expanded` with no `aria-controls`** | Screen readers couldn't associate the toggle with its panel | Wired up in JS |
| 18 | Duplicate `.badge-avail .dot` rule; `scroll-behavior` declared twice | Code smell | Consolidated |

### P1 — Still on you (I can't do these from here)

- **Create `/og-image.jpg`** at 1200×630. Right now every share is a naked URL.
- **Convert `hero-bg.png`, `portrait.png`, `about-bg.png`, `cta-bg.png` to WebP.** Full-bleed photographic PNGs are the single biggest performance liability on the page — expect a 60–80% weight reduction.
- **Create the favicon set** (`favicon.ico`, `favicon.svg`, `apple-touch-icon.png`, `site.webmanifest`).
- **Verify the LinkedIn URL** I used as a placeholder: `linkedin.com/in/carlmadelo/`.
- **Substantiate the stats.** "40% avg. increase in lead requests" and "12+ projects" need to be defensible. If they aren't measured, soften them — a false claim in an `ItemList` context is a real risk, not a theoretical one.
- **Ship `robots.txt` and `sitemap.xml`** — both are generated by the build script.
- **Add Search Console + Bing Webmaster**, submit the sitemap.
- **Get a phone number on the page** if you take calls. Right now the only conversion path is a mailto.

### The structural problem

Everything above is worth doing and none of it changes the outcome much on its own. **A one-page site has one ranking surface.** You can rank for "Carl Madelo" and, with luck and links, brush the top 20 for "Duda web designer" — a term with maybe a few hundred global searches a month, most of them other freelancers.

That's what Part 2 is for.

## Part 2 — Programmatic SEO strategy

### Opportunity assessment

You are a new domain with no authority, in a narrow niche, competing with Duda's own marketing site and agency directories. That rules out head terms. It rules *in* commercial-intent long tail where the competition is thin and your first-hand experience is the differentiator.

Three clusters, ranked by ROI:

| Cluster | Pattern | Why it works for you | Pages |
|---|---|---|---|
| **Migrations** | `/migrate-to-duda/[platform]/` | Highest commercial intent on the site. Someone searching "wix to duda migration" is a buyer, not a browser. Almost no competition — Duda's own docs are thin here. | 5 |
| **Comparisons** | `/duda-vs/[platform]/` | Real search volume, and you can write these from delivered projects instead of feature tables. Your bias is a feature if you're honest about it. | 6 |
| **Industries** | `/duda-web-design/[industry]/` | Backed by actual portfolio proof — construction, home services, property. This cluster only works where you have a live build to link. | 4 |

**Deliberately excluded: location pages.** You have no local presence and no per-city proof. "Duda web designer in Manchester" with the town name swapped is the textbook thin-content pattern, and it's the fastest way to get the whole domain treated as low quality. Revisit only if you accumulate real projects per city.

### Data defensibility

Everything here is tier-1 or tier-2 on the defensibility ladder: **your own delivered builds** and **your own migration process**. That's the entire moat. Nobody else can write "here's what broke on the last three Wix migrations I did." The moment you start paraphrasing vendor feature pages, the cluster becomes worthless.

### Architecture

```
/                                   hub of hubs (homepage Guides section)
├─ /duda-vs/                        cluster hub
│  ├─ /duda-vs/wordpress/           ✅ published, 989w
│  ├─ /duda-vs/wix/                 ✅ published, 911w
│  └─ /duda-vs/{squarespace,webflow,gohighlevel,godaddy-website-builder}/   noindex stubs
├─ /migrate-to-duda/
│  ├─ /migrate-to-duda/wix/         ✅ published, 1010w
│  └─ /migrate-to-duda/{wordpress,squarespace,godaddy,weebly}/              noindex stubs
└─ /duda-web-design/
   ├─ /duda-web-design/construction/  ✅ published, 860w
   └─ /duda-web-design/{home-services,real-estate,professional-services}/   noindex stubs
```

Subfolders, never subdomains. Every page is reachable from the homepage in two clicks via the new **Guides** section — no orphans. Comparison pages cross-link to their matching migration guide and vice versa, which is the internal-linking pattern that actually moves rankings in a small cluster.

### The anti-thin-content mechanism

`build.mjs` enforces two conditions before a page is indexable:

1. `status: "published"` in the data file
2. **≥ 600 words of unique body copy** (measured after stripping tags — boilerplate doesn't count)

Fail either and the page ships with `noindex, follow`, is excluded from `sitemap.xml`, and gets no `FAQPage` schema. It still renders and is still linked from its hub, so the crawler discovers it the moment you flip it live.

This means **you can commit all 15 stubs to the repo today** and only the finished ones get indexed. Run the build and it prints exactly which pages are being held back and why.

### Content rules per page

Non-negotiable, or the cluster degrades into a doorway farm:

- **≥ 600 words unique.** The build enforces it.
- **A unique intro, verdict and FAQ set.** Never reuse a paragraph across two pages.
- **At least one place where you say the competitor wins.** This is the whole credibility play. The WordPress page says WordPress is better for extensibility and data ownership, because it is.
- **A link to a real build where one exists.** The `proof` block.
- **No pricing figures unless verified that week.** I deliberately left all pricing out of the copy — vendor pricing changes and a wrong number is worse than no number.

### Rollout sequence

1. **Weeks 1–2** — Ship the homepage fixes + the three published pages. Get Search Console reading the sitemap.
2. **Weeks 3–6** — Finish the migration cluster (WordPress, Squarespace, GoDaddy, Weebly). Highest intent, do it first.
3. **Weeks 7–10** — Finish the comparisons. GoHighLevel is your differentiator here; almost nobody has written it and you actually build in both.
4. **Weeks 11+** — Industry pages, but only as portfolio proof accumulates. Ship three good ones, not eight hollow ones.

### What to watch

- **Indexation rate.** If published pages sit unindexed past ~3 weeks, the problem is authority, not content — go get links.
- **Impressions before clicks.** Impressions rising with flat clicks means the pages rank on page 3. Normal for months 1–3.
- **Query drift.** Search Console will tell you which long-tail phrasings actually pull. Fold them into existing pages rather than spawning new ones — keyword cannibalisation is the failure mode at this scale.
